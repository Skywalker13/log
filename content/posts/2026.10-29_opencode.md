Cet article a pour vocation de présenter comment mettre en place un outil comme
[OpenCode] et d'utiliser une IA générative (LLM) de manière un peu plus
responsable que par le biais d'entreprises tierces auxquelles on ne devrait pas
accorder sa confiance.

Les modèles dits "open source" actuels sont largement assez puissants pour
répondre aux "besoins" qu'on imagine nous faire croire. Alors si vous souhaitez
être moins complice des méfaits internationaux, je vous encourage à tester des
alternatives comme celle que je décris ci-dessous.

## Environnement

Avant tout, il ne faut pas négliger la sécurité. Malheureusement il y a bien
trop de laxisme dans le monde professionnel. Un LLM ne doit **jamais** avoir
directement accès à vos droits utilisateur et encore moins à des droits
administrateurs. Cet [excellent article de Willy Tarreau][1] suffit à lui-même,
néanmoins je tiens à personnaliser son approche pour exploiter un LLM chez un
fournisseur tiers.

### Un compte utilisateur dédié

On crée un compte utilisateur `ai` et on fait en sorte que son propre
utilisateur puisse y accéder en écriture.

```sh
sudo useradd -m -s /bin/bash ai # créer le compte
sudo usermod -aG ai votre_compte # insère votre_compte dans le groupe ai

sudo chmod -R 770 /home/ai # donne les droits complets au groupe ai
sudo chmod -R g+s /home/ai # pose l'héritage par le groupe

sudo setfacl -R -m g:ai:rwx /home/ai
sudo setfacl -R -d -m g:ai:rwx /home/ai
```

Avec ces quelques lignes, `votre_compte` peut accéder en écriture au contenu de
`/home/ai` et on fait en sorte que tout ce qui est créé dans ce compte, hérite
du groupe `ai`.

> Avant de poursuivre, **vous devez vous déconnecter de votre_compte puis vous
> reconnecter.** Si vous ne souhaitez pas le faire, vous pouvez simplement vous
> reconnecter dans un terminal ainsi :  
> `su - votre_compte`

Ainsi, vous n'avez pas à mettre à disposition du compte `ai`, des clefs telle
que pour le SSH. Vous clonez et synchronisez vos dépôts Git simplement avec
votre compte utilisateur habituel. Mais bien entendu, vous les clonez dans
`/home/ai` afin que l'IA puisse y accéder à travers [OpenCode]. Une fois cloné,
il faut s'assurer de partager ce dépôt avec le groupe (sinon l'utilisateur `ai`
n'aura pas les droits d'écriture) :

A faire dans chaque dépôt concerné !

```sh
git -C /home/ai/devel/mon_depot config core.sharedRepository group
chmod -R g+rwX /home/ai/devel/mon_depot
```

Pour accéder au compte `ai`, il suffit alors de ne faire plus que :

```sh
sudo -iu ai
```

> N'oubliez pas que le compte `ai` suit les droits unix habituels.

## Agentique via un terminal

**Soyez honnête, montrez qu'est-ce qui commit**

Je recommande de montrer explicitement qu'est-ce qui commit dans les dépôts. Il
est malvenu de cacher du code généré sous votre propre identité. Il est surtout
beaucoup plus clair de faire la part des choses et de faire le tri dans ce qui
est produit.

```sh
# depuis le compte ai
git config --global user.name "AI Agent"
git config --global user.email "ai@localhost"
```

### Déployer [OpenCode]

Il existe de nombreux logiciels pour faire de l'agentique depuis un terminal.
[OpenCode] semble être un des plus populaires aujourd'hui, tout en étant
open-source. Je vous encourage vivement à ne jamais utiliser de logiciels
propriétaires.

```sh
# depuis le compte ai
curl -fsSLO https://opencode.ai/v2/install && bash install
```

Je ne suis pas un partisan de ces outils mais ma fois, c'est une étape presque
devenue obligatoire. Une fois installé, il faut sortir et rerentrer dans le
compte `ai` pour bénéficier de l'environnement à jour.

## Quel modèle utiliser

Tout dépend de ce que vous avez à disposition ou non. Je vous renvoie sur
l'article de [Willy Tarreau][1] qui présente tout ce qu'il y a à faire pour
faire de l'inférence en local avec [llama-cpp].

Mon but ici est de vous montrer comment exploiter un tiers de confiance. A qui
vous accordez votre confiance est votre problème, ici j'ai envie d'accorder la
mienne à la société [Infomaniak] que je connais depuis des décennies.

## Mettre en pratique

Imaginons que vous avez déployé un dépôt dans `/home/ai/devel/mon_depot`. Je
vous invite à démarrer [OpenCode] depuis celui-ci.

```sh
# depuis le compte ai
cd devel/mon_depot
opencode .
```

C'est désormais très simple. Depuis le prompt d'[OpenCode], faites `/connect`.
Choisissez `infomaniak` dans la liste, sélectionnez le modèle Kimi K2.6 puis
inscrivez votre clef API.

> Soyez conscient que le LLM a accès à cette clef API. Mais ici, au moins, elle
> n'ira pas plus loin que chez [Infomaniak] qui l'a connait déjà.

C'est tout, à partir de maintenant vous pouvez faire du vibe-coding ou tout ce
que vous voulez avec un modèle très costaud.
